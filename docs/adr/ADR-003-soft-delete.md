# ADR-003：软删除 + 回收站，不做硬删除

## 状态
Accepted（2026-11-09 追认）

## 背景
教学数据删错一个学生 = 一个孩子的全部历史消失。硬删除在多设备同步下还意味着
「删除这个动作本身要参与同步决胜」，失败模式复杂。

## 决策
删除一律是**软删**（`removed: true` 普通字段），参与 LWW 同步；
软删的行进回收站（`utils/db/trash.js`，每类保留 60 条）可恢复。
版本历史（`cloudfunctions/syncv2` 的 HIST_COLLS）只覆盖四类核心资产
（orgs/members/students/classes），记录类不存历史（海量增长，撑爆库）。

## 后果
- **得**：误删永远有退路；「删除」与「编辑」在同步协议里是同一种东西，模型简单。
- **失**：存储不真正回收（腾空间靠存储页的清理功能单独做）；
  恶意/合规要求的「彻底抹除」没有通道（当前无此需求，有再说）。
