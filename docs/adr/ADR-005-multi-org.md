# ADR-005：多机构 = orgId 全局作用域 + 成员工牌制 + 按班级订阅

## 状态
Accepted（2026-11-09 追认；按班级订阅为当日落地）

## 背景
一个微信可能属于多家机构（老师兼职、负责人开分店、家长两家都报课）。
本地库是「全量库」，读取按 `meta.orgId` 过滤；云端按 orgId 物理隔离。

## 决策
- **身份模型**：users（微信号）+ members（每机构一条「工牌」，含角色与范围）。
  权限只看工牌，不看微信号本身。
- **负责人**（owner）：一机构唯一、不可删、转移必须显式「移交负责人」、不受班级范围限制。
- **按班级订阅**（2026-11-09 落地）：老师端 pull 只拉自己带的班
  （students/records/enrollments/classes 四集合按班级过滤，没分班 = fail-closed 什么都拉不到）。
  老师手机的存储量从「机构规模」变成「班级规模」。负责人/管理员保持全量（他们管全机构）。
- **游标是过滤条件的函数**：老师新分班/家长新绑孩子（工牌范围变化）时，
  客户端检测到变化 → 该机构游标归零重拉（`meta.sync.rescoped` 队列，杀进程不丢）。

## 后果
- **得**：机构再大，老师端的存储与首拉时间不随机构规模增长；家长跨机构看同一孩子天然成立。
- **失**：服务端 pull 的 where 构造按角色分支（复杂度集中一处）；老师端看到的数据
  依赖工牌上的 clsIds——管理员分班后要等一次同步才生效（游标重拉机制保证生效）。
