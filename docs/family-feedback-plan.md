# 家长反馈闭环方案（已读回执 + 家长留言）

> 状态：**方案待拍板，未改任何代码**。
> 提出：2026-11-07 23:03。用户原话要点：「每个学生家长看没看过这个消息，要有一个反馈」；
> 「家长要增加一个回复通道，对这次课程、对老师有建议、表达感谢或别的意见，都能反馈出来」。

---

## 1. 现状：为什么不能直接在记录表上加两个字段

- **家长端是只读的**：权限层 `utils/db/permissions.js` 只给家长 `profile.write`；记录靠 `sent`
  决定对家长可见。家长首页 / 学生档案能看到分数、照片、语音、评语，但没有任何回执或输入框。
- **现在的通知是单向的**：`cloudfunctions/family` 用一次性订阅消息在老师发布时推一条微信服务通知，
  `openid_map` 只登记「订阅过通知」的家长；发出去就结束，没有已读，也没有回话的地方。
- **同步表不能碰**：`syncv2` 的 `COLLS` 里 `records` 等按 `orgId` 全量 pull；`push` 除 `members`
  外服务端没有角色校验（历史遗留，客户端拦了但云端 fail-open）。把已读/留言塞进同步集合，
  等于把别家孩子的留言同步到所有设备，家长还能伪造写入。
- 架构守卫钉死「客户端 0 处直连数据库」，所有写入必须走云函数。

**结论**：新增两张**云端专属表**（不进 `COLLS`），由 `family` 云函数按「这个微信到底是谁、绑的是哪个孩子」
做服务端鉴权后读写。现有 `record.sent` 发布链路一行不动。

---

## 2. 目标与口径

| 项 | 口径 |
|---|---|
| 已读 | 家长**真正打开某条已发布成果的详情**才算已读；进首页、收到微信服务通知都不算（避免假已读）。自动上报，不用点按钮 |
| 留言 | 家长对某条成果给老师留话：建议 / 感谢 / 意见。200 字内，文字或语音转文字，过内容安全 |
| 老师端 | 看得到「谁看了、谁没看」和「家长说了什么」，可标记已处理 |
| 家长端 | 看得到自己写过的留言与处理状态；看不到别人家孩子的任何内容 |

---

## 3. 数据：两张云端新表（不进同步集合）

```
record_views   { id: orgId+':'+rid+':'+openid, orgId, rid, sid, openid, viewedAt }
parent_notes   { id, orgId, rid, sid, openid, text, createdAt,
                 handled, handledBy, handledAt }
```

- 已读按复合 id 用 `.doc(id).set()` **幂等**；写入的 `data` 里绝不带 `_id`（`admin` 云函数踩过
  `-501007 不能更新 _id`）。
- 同一家长对同一条记录最多 3 条留言，60 秒内最多 2 条（防刷屏）。
- 首次调用自动建表（`ensureCollections` 口径），索引按现有文档建 `orgId + srvAt`（或
  `orgId + createdAt`）复合；已读幂等靠 doc id，不依赖唯一索引。
- 两张表只存 `sid / rid`，**不存成绩、照片、学号、手机号**；姓名由各端按自己的权限补出。

## 4. 云端接口：只改 `family` 一个云函数

身份统一：`cloud.getWXContext().OPENID` → `members` 表查该机构成员。
家长按 `studentIds` 判「是不是自家孩子」；老师 / 负责人按 `clsIds` 或管理级判范围。
**fail-closed**：查不到成员、查不到绑定、字段不自洽一律拒绝，不信前端传来的 sid / role。

| action | 谁 | 做什么 |
|---|---|---|
| `fbView({rid, sid})` | 家长 | 校验 sid 属于自己 → upsert 已读 |
| `fbNote({rid, sid, text})` | 家长 | 校验 → 限流 → `cloud.callFunction(secCheck, {action:'msg', content})`（87014 拒绝）→ 落库 |
| `fbList({scope, since})` | 两端 | 家长只回自家孩子的留言；老师只回自己可见班级的留言，分页 |
| `fbStats({rids})` | 老师 | 批量回 `{rid: {viewed, notes, unhandled}}`，给列表小标用 |
| `fbHandle({id})` | 老师 | 标记已处理 |

`utils/api.js` 加对应封装（沿用 `callFn` + `syncOn()` 判云是否通）；云未通时前端**静默降级**，
入口隐藏，不弹「网络错误」吓家长。

## 5. 两端界面

**家长端**
- 打开成果详情时静默上报 `fbView`；失败不提示、不阻塞，下次进来重试。
- 详情底部「**给老师留句话**」：输入框 + 全站通用麦克风（同声传译转文字，**不收语音附件**）
  → 提交 → 显示「已送达老师」；下方列出自己写过的留言和处理状态。
- 未绑定孩子 / 云未通时入口不显示。

**老师端**
- 新页 `pages/feedback`：留言列表（孩子 · 课程 · 日期 · 内容 · 时间 · 标记已处理），未处理置顶，可按班级筛。
- 记录列表与班级页：每条已发布记录加「**家长已看 / 未看**」小标。
- 首页 / 班级页统计「本次课 x/y 家长已看 · N 条新留言」+ 红点。
- 一期**不推微信通知给老师**（老师没有订阅额度、模板也没申请）：靠进小程序的红点触达，
  老师侧推送放阶段 2。

## 6. 隐私与安全边界

- 留言只对「该生绑定的家长 + 本机构有权限的老师」可见，服务端按 `members` 判定。
- 已读 / 留言**不进本地数据层、不进同步集合**：家长端不会全量拉到别家的反馈。
- 文字过 `secCheck`，命中 87014 明确提示「这段话发不出去，请改一下」，不静默吞掉。
- 家长不能改老师记录（现有 `record.update` 只给老师，保持不变）；老师不能改家长留言，只能标记已处理。
- 一张成果一个家长限 3 条 + 频率限制；已读上报天然幂等。

## 8. 成本、部署坑与回滚

- **无新增付费**：两张表 + 云函数调用；`secCheck` 按次（现有能力）。
- **部署坑**：`cloudfunctions/family/config.json` 目前**没有 `timeout` 字段**，20 秒是早先在控制台
  手工改的。重部署可能把超时打回 3 秒 → 实施时先给 config 补 `"timeout": 20`，
  再 `npm run cloud -- family`，之后 `npm run cloud:info` 复核 7 个函数全 Active、超时 ≥20 秒。
- **回滚**：隐藏两端入口 + 关掉 5 个 action 即可；`record.sent` 老链路不变，已发布的记录、
  已加入的家长都不受影响。
- **顺带发现（不在本轮修）**：`syncv2` 的 `push` 除 `members` 外没有服务端角色校验，
  家长理论上能伪造 push。建议单独一轮补服务端 ACL，不要和这次功能混在一起改。
