# 数据库索引：照着点一遍就行（约 5 分钟）

> 这份是给「两个索引怎么详细设置」补的操作步骤。不建也能跑，
> 但绑定表以后会涨到几千行，没索引时每次同步都要全表扫描，到时候变慢就不好排查。
> **建完立即生效，不用重新部署云函数、不用重启小程序、不用清缓存。**

## 一、进到索引管理页面

1. 打开微信开发者工具 → 顶部工具栏点 **云开发**
2. 左侧选 **数据库**
3. 集合列表里点 **`class_courses`**（班级-课程开设关系表）
4. 右侧上方切到 **索引管理** 标签页
5. 点 **新建索引**（有的版本叫「添加索引」）

## 二、建两个复合索引

### 索引 ① 班级的排课表

| 要填的 | 填什么 |
|---|---|
| 索引名称 | `org_cls`（自己起，字母数字下划线，别用中文） |
| 字段 1 | `orgId`，排序 **升序** |
| 字段 2 | `clsId`，排序 **升序** |
| 是否唯一 | **否**（一定要选否） |

点「添加字段」加第二行，两个字段都加完再确定。

### 索引 ② 这门课在哪些班

| 要填的 | 填什么 |
|---|---|
| 索引名称 | `org_course` |
| 字段 1 | `orgId`，升序 |
| 字段 2 | `courseId`，升序 |
| 是否唯一 | **否** |

**为什么必须选「非唯一」**：一个班有多门课、一门课会开在多个班，
`orgId + clsId` 这个组合本来就会重复；选了唯一索引，第二条排课就写不进去了。
这是这步最容易点错的地方。

## 三、顺带建议的三条（不急，但一起建最省事）

增量同步的查询形状是 `where({ orgId, srvAt > 游标 }).orderBy('srvAt')`，
没有 `orgId + srvAt` 复合索引就会退化成扫描。在各自的集合里重复上面的动作：

| 集合 | 索引名称 | 字段（都升序，非唯一） |
|---|---|---|
| `class_courses` | `org_srv` | `orgId` + `srvAt` |
| `records` | `org_srv` | `orgId` + `srvAt` |
| `students` | `org_srv` | `orgId` + `srvAt` |

> 不同集合可以用同一个索引名，互不冲突。
> `srvAt` 是同步时间戳，部分旧行可能没有这个字段——不影响建索引，也不影响查询。

## 四、建完怎么确认

索引管理列表里应该看到 5 条新索引（`class_courses` 三条，另两张表各一条）。
去小程序 **我的 → 存储空间 → 立即同步**，同步能正常完成、没有报错，就算好了。

## 五、可能遇到的提示

| 提示 | 原因 / 怎么办 |
|---|---|
| 「索引已存在」 | 之前建过了，列表里能看到就行，不用再建 |
| 「名称不合法」 | 索引名换了纯英文小写 + 下划线，别带空格中文 |
| 「字段不存在」 | 字段名严格照抄 `orgId` / `clsId` / `courseId` / `srvAt`，大小写不能错 |
| 建完感觉没变化 | 正常的，数据量小时看不出差别，收益在几千行之后 |

## 六、为什么这件事只能人工点

微信云开发的**索引管理没有开放给 CLI 或云函数的接口**：
命令行能部署云函数（`npm run cloud`）、能自动建集合（`syncv2.ensureCollections()`），
但建索引没有对应 API。所以这 5 条只能控制台点一次，点完一劳永逸。
