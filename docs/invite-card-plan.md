# 家长免码加入 · 一人一卡方案（定稿 2026-11-07）

> 状态：**方案已定稿，尚未动代码**。
> 讨论记录见 `docs/handoff.md` 19:42 / 19:48 两节；本文件是后续实施的唯一依据。

## 一、结论与方向

**微信无法判断「这个用户是不是学生家长」**。小程序能拿到的只有：

| 能力 | 怎么拿 | 能说明什么 |
|---|---|---|
| `openid` / `unionid` | `wx.login()` 静默 | 只是「这个微信在本小程序里的匿名编号」，与社会身份无关 |
| 头像、昵称 | 用户主动授权 | 不能当身份凭据 |
| 手机号 | 点按钮触发系统授权弹窗 | 只是号码本身，**不是验证码**；需非个人主体 + 已认证，0.03 元/次（1000 次免费额度） |

微信不开放实名信息、不开放「谁是谁的家长」这类关系。所以不去做「识别家长」，改成：

> **老师把入口送到家长手边，家长点一下确认。身份判定的责任放在老师（录入名单）和后台（令牌/手机号比对），不放在家长的记忆里。**

现状要拆掉的记忆负担：家长加入 `pages/join/join` 现在要填 **6 位机构码 + 4 位孩子学号** 两样东西。定稿后两样都不用记。

## 二、定稿决策（用户 19:52 确认「可以」）

| 决策点 | 定稿值 |
|---|---|
| 邀请粒度 | **一人一卡**，卡面写明孩子姓名，直接认领到具体孩子 |
| 发送方式 | **两种都做**：① 单发：老师私聊把专属卡发给该生家长；② 群发：一张「整班卡」发到班级群，家长点开后点自己孩子姓名再确认 |
| 群里形态 | 群发用**整班卡**（群里只有一条消息，不刷屏）；专属卡用于私聊与「还没确认的家长」补发。两者共用同一套后台 |
| 确认强度 | **默认「老师通过才生效」**，管理页出「待确认家长」列表，一键通过/拒绝；机构熟了可关掉开关 |
| 卡面内容 | 孩子姓名 + 班级 + 机构名 +「点一下确认，看孩子的课堂成果」。**不写学号、手机号、成绩，默认不放照片**（群里是公开的） |
| 有效期 | **7 天 + 一次性**；老师可随时作废 / 重发 |
| 手机号加固 | 列为阶段 3 可选项，取决于小程序主体是否已认证、是否接受按次费用 |

用户原话要点：「一个班十个人，可以单个发给学生家长，也可以把十张卡片都发到群里，自己的家长去点自己孩子姓名的卡片进行确认」——整班卡 + 专属卡正是覆盖这两种发法。

## 三、核心实现洞察（为什么改动比看起来小）

**卡片不是一套新的身份体系，而是把现有「机构码 + 孩子学号」预封装成一次性令牌。**

```
老师点「发卡片」
  → 云端为 (机构, 角色 parent, 学生 sid) 生成一次性 token，存 invite_cards
  → 微信分享卡片 path = /pages/join/join?card=<token>（或小程序码 scene=<token>）
家长点开
  → cardInfo(token) 反查：机构名 / 班级 / 孩子姓名 / 卡片状态（不回学号、手机号）
  → 确认页「你是【张小明】的家长吗？→ 我是，确认」
  → cardClaim(token, 姓名[, 手机号]) 服务端换回 code + stuNo
  → 复用现有 inviteJoin 落库（成员表、openid、兄弟姐妹）
  → 复用 sync.join() 拉回本机 → 落孩子档案页
```

因此 **`inviteJoin` 的落库逻辑、权限层、成员表、`claimOpenid()` 几乎不用动**，主要工作是新增一张表和几个 action，以及两端界面。

## 四、两种卡的形态

### 4.1 专属卡（一人一卡，私聊 / 补发）
- 微信分享卡片：`onShareAppMessage` 动态设置 `title` 为「张小明 · 课堂成果邀请」、`path` 为 `/pages/join/join?card=<token>`。
- 可选：小程序码图片（`cloud.openapi.wxacode.getUnlimited`，`scene` ≤ 32 字符，token 要短），用于打印 / 贴教室门口。
- 卡片状态：`unused → claimed(待审核) → approved(生效)`，或 `revoked / expired`。

### 4.2 整班卡（群发，一张卡带名单）
- 一条分享消息，title「XX 班 · 家长确认入口」，path 带 `classToken`。
- 点开先出**名单页**：只列孩子姓名（不带照片、不带学号），家长点自己孩子姓名 → 后端按选中的 `sid` 找或生成该孩子的专属 token → 走同一确认页。
- 群里任何家长都能看到全班姓名，这是必要的最小暴露；**不显示任何成绩、评语、联系方式**。
- 已被认领的孩子在名单里标「已确认」，避免重复点。

## 五、数据结构（新增 `invite_cards` 集合）

| 字段 | 说明 |
|---|---|
| `_id` | 一次性 token（随机短串，不可猜；不用自增 id） |
| `orgId` / `clsId` / `sid` | 机构 / 班级 / 学生；整班卡 `sid=0` + `clsId` 有值 |
| `code` | 该机构现存的家长邀请码（反查用，卡片不外泄） |
| `role` | 固定 `parent`（老师/管理员仍走老的机构码入口） |
| `expiresAt` | 生成时间 + 7 天 |
| `usedAt` / `usedBy` | 一次性：被谁在什么时候确认过 |
| `status` | `unused / pending / approved / revoked` |
| `claimName` / `claimPhone` | 家长确认时填的姓名、可选授权手机号 |
| `by` / `createdAt` | 生成的老师 openid / 时间 |

**并存原则**：现有 `invites`（一机构一角色一码、30 天、可重复使用）**完全保留**，老入口与已发出去的码不回归；新表只服务家长卡片。

## 六、云端 action（加在 `cloudfunctions/syncv2/index.js`）

| action | 权限 | 作用 |
|---|---|---|
| `cardCreate` | 负责人/管理员全可；老师只能给自己带的班发家长卡 | 生成专属卡或整班卡 token |
| `cardInfo` | 无需绑定机构（家长还没加入） | 只回机构名、班级名、孩子姓名、卡片状态；**不回学号 / 手机号 / 任何业务数据** |
| `cardClaim` | 无需绑定机构 | 校验一次性 + 有效期 → 换回 `code/stuNo` → 落 `pending` 成员 → 标记 used |
| `cardList` | 本机构管理权限 | 老师端「待确认家长」列表 + 各卡状态 |
| `cardApprove` / `cardReject` | 本机构管理权限 | 通过 / 拒绝；通过后成员 `active` |
| `cardRevoke` | 生成者或管理员 | 作废 / 重发 |

> `cardApprove` 之类已绑定机构才能调的 action，必须放在 `userOf(OPENID)` 校验之后；
> `cardInfo` / `cardClaim` 必须放在之前（家长还没绑定）。现有 `inviteInfo` / `inviteJoin` 就是这么分层的。

## 七、安全与隐私（群发场景是重点）

群里十张卡谁都能点，所以**「点一下就绑上」不允许**：

1. 确认页必须显式二次确认：「你是【张小明】的家长吗？」+ 填自己姓名，按钮不是「下一步」而是「我是，确认加入」。
2. token 一次性 + 7 天过期 + 老师可随时作废重发；卡里**只有 token**，不带学号、不带机构码明文。
3. 默认老师审核：确认后成员 `status:'pending'`，权限层对 pending 返回空数据（家长看到「已提交，等老师确认」）；通过后 `active`，下次同步即可见。开关可关。
4. 可选增强（阶段 3）：家长授权手机号与库里 `parentPhone` 比对，一致直接通过、不一致强制转人工。
5. 防串号：token 绑定具体 `sid`，点别人的卡不会把孩子认错；`studentSiblings()` 把同家长兄弟姐妹一起带出。
6. 老入口保留，避免「已经发出去的 6 位码」突然失效。

## 八、现有代码复用清单与必须补的点

**可直接复用**
- `pages/join/join.js` 已支持 `?code=` 带参进入（自动填码并校验）→ 扩成 `?card=` 分支即可。
- `api.inviteInfo` / `api.inviteJoin` / `utils/sync.js join()` / `db.claimOpenid()` / 成员表 `openid` 字段。
- `pages/mine/mine.js inviteMenu()` 的「先同步一轮再取码」防坑逻辑。
- `pages/mgr` 的点名绑孩子弹层（G05）可复用成「发卡片」名单选择。
- `utils/db/students.js studentSiblings()` 手机号 + 微信双键归并。

**必须补齐的两处不一致**
- 云端 `inviteJoin` 的兄弟姐妹归并**只用 `kid.wechat`**，客户端已支持 `parentPhone` 双键（F-04 新增字段没同步到云端）。阶段 1 要对齐，否则填了手机号却带不出兄弟姐妹。
- `sync.join()` 要求**本机空库**。家长首次打开通常满足；已有别的机构数据时，确认页要提前检测并给「先到存储空间清空」的指引（`LOCAL_DATA` 提示已有，别让它变成加入失败才看到）。

## 十、分阶段实施与验收

| 阶段 | 内容 | 验收 |
|---|---|---|
| **1 · 最小闭环** | `invite_cards` 表 + `cardCreate/cardInfo/cardClaim`；老师端「发专属卡」；家长点卡确认；一次性/7 天/作废；云端 `parentPhone` 归并对齐 | 单元：token 重复用被拒、过期被拒、作废被拒、点开只回姓名不回学号；真机：老师发一张卡 → 家长点开 → 确认 → 直接进孩子档案 |
| **2 · 群发与审核** | 整班卡名单页；`cardList/cardApprove/cardReject`；管理页「待确认家长」；pending 权限层 | 真机：一张卡发群 → 两个家长各点自己孩子 → 老师逐一通过 → 各只看到自己孩子；未通过看不到数据 |
| **3 · 可选加固** | 手机号一键认领（主体认证后）；老师批量重发未确认卡片；案例墙 / 价格口径文案 | 手机号一致自动通过、不一致转人工；按次费用在后台可查 |
| **4 · 老师首入体验** | 演示样板间提到首屏第一屏；3 分钟产出一张成果卡；首屏一句话价格口径；脱敏案例 / 邀请同行入口 | 新老师首次打开不填任何表就能看到「家长收到是什么样」 |

**每阶段都要跑**：`node tools/lint.js`、`node tools/schema-doc.js --check`、`node tests/run.js`（新增 `tests/verify_invite_card.js`）、提交 GitHub、`npm run ship`。云函数改动按第九节重部署并复核超时。

## 十一、回滚

卡片是**新增旁路**，不替换现有机构码。出问题时把老师端「发卡片」入口隐藏 + `cardCreate` 关掉即可，已加入的家长不受影响；`invites` 老入口始终可用。
