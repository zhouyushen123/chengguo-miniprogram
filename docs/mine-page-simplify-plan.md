# 「我的」页简化方案（2026-11-08）

> 只出方案，未改代码。目标是：**一屏看完、每行都有人用**。
> 现状：负责人打开「我的」要面对 1 张身份卡 + 6 格统计 + 换肤 + 12 行入口 = **20 个块**，
> 其中 5 个是"一辈子点一次"的配置项，全铺在首屏。

## 一、现状盘点（负责人视角，12 行入口）

| # | 入口 | 谁在用 | 频次 | 判断 |
| --- | --- | --- | --- | --- |
| 1 | 看演示数据 | 新用户 | 一次 | 应挪走 |
| 2 | 机构入驻申请 / 机构信息 | 负责人 | 一次 | 应挪走 |
| 3 | 电脑端后台 | 负责人 | 偶尔 | 应挪走 |
| 4 | 邀请成员 | 负责人 | 偶尔 | **留**（拉人是真高频的事） |
| 5 | 开通引导 | 新机构 | 一次 | 只在空库时出现 |
| 6 | 学期管理 | 负责人 | 每学期一次 | 应挪走（与课程/班级同处） |
| 7 | 切换身份（演示） | 开发/演示 | 极少 | 应挪走（不该出现在正式菜单） |
| 8 | 家长反馈 | 老师/负责人 | 每天 | **留**（要带未读数） |
| 9 | 再加一家机构 | 多机构老师 | 一次 | 应挪走（进「机构与身份」） |
| 10 | 存储空间 | 所有人 | 出问题时 | 应挪走（放「设置」） |
| 11 | 关于橙果 | 所有人 | 一次 | 应挪走 |
| 12 | 输入邀请码加入 | 未加入的人 | 一次 | 保留，但与首页开通卡重复 |

## 二、诊断：不是"内容多"，是三类东西混在一起

1. **身份/机构**（我是谁、在几家机构、怎么进另一家）
2. **日常工作**（今天要处理什么：家长反馈、班级学生）
3. **配置**（邀请、学期、演示、存储、关于）

三类混排的结果：每天要点的那一条（家长反馈），被夹在"入驻申请"和"开通引导"中间，
需要往下找。**简化不是把功能砍掉，是把它们放回各自该在的层。**

## 三、新结构：一屏 5 块

```
┌───────────────────────────────┐
│ 头像  王老师 · 负责人            │  ← 身份卡（点整张 → 机构与身份）
│       橙果美术 · 全机构可见   ›  │
├───────────────────────────────┤
│  学生 42   班级 6   课程 9      │  ← 三个数字，只留最常看的
├───────────────────────────────┤
│  家长反馈       3 条未处理   ›  │  ← 每天要点的，带红点
│  邀请成员                    ›  │  ← 负责人拉人
├───────────────────────────────┤
│  设置                        ›  │  ← 二级页装下其余全部
└───────────────────────────────┘
```

首屏从 **20 块 → 5 块**；其余进两个二级页，两级都还是一屏。

### 二级页 A：机构与身份
- 当前机构（多家时可切换）
- 再加一家机构
- 机构资料（原「机构入驻申请 / 机构信息」）
- 电脑端后台（账号 + 口令 + 重置）
- 邀请成员（家长码 / 老师码 / 管理员码）

### 二级页 B：设置
- 学期管理
- 开通引导（仅空库时显示，或用完即隐藏）
- 存储空间（占多少、清理、待上传条数）
- 看演示数据 / 退出演示
- 切换身份（演示）
- 关于橙果

## 五、家长视角单独裁

家长打开「我的」只该有三样：**孩子是谁**（可切换）、**存储空间**（手机空间）、**关于**。
现在家长看到的是同一套菜单（只是少了管理项），仍偏"机构后台"的味道。
建议家长版首屏 = 身份卡 + 「我的孩子」列表 + 设置（两项）。

## 六、分期

**P0（约半天，收益最大）**
1. 抽出「机构与身份」「设置」两个二级页，把 8 个低频项搬过去
2. 首屏按上面的 5 块重排
3. 统计层 6 格 → 3 格

**P1（约一天）**
4. 家长反馈红点（未处理数）接到首屏
5. 家长视角裁剪
6. 「开通引导」按空库条件自动显隐

## 七、风险与取舍

- **别把"能看见"当成"必须放首屏"**：搬进二级页的功能要保证一次能点到，不能三级。
- **红点只给真人要处理的**：家长反馈可以有数字；"存储空间""关于"不挂任何角标。
- **统计层砍 3 格会有意见**：老师数/家长数是负责人偶尔想看的，所以放「邀请成员」页顶部而不是直接删。
- 迁移期间旧入口先保留（一次性跳转），确认没人用再删，避免用户"找不到按钮"报障。

## 八、实施记录（2026-11-08 13:1x，已改代码）

按 P0 三条全部落地，并顺带把 P1 的三条一起做了（成本都是几行）。

### 落地结果
- 首屏 **20 块 → 5 块**：身份卡（整张可点）/ 三个数字 / 家长反馈（带未读数）/ 邀请成员 / 设置。
- 新增两个二级页，都是一屏：
  - `pages/orgid/orgid` **机构与身份**：当前机构 + 家长数·老师数、切换机构（≥2 家才出现）、
    再加一家机构、机构入驻申请 / 机构资料、电脑端后台、邀请成员。
  - `pages/setting/setting` **设置**：学期管理、开通引导、输入邀请码加入（空库才出现）、
    存储空间（副标题带待上传 / 被退回条数）、看演示数据、切换身份、关于橙果、外观（换肤）。
- 统计 6 格 → 3 格（学生 / 班级 / 课程）；**家长数、老师数放在「机构与身份」顶部**
  （原方案的「邀请成员页顶部」：邀请成员是弹层不是页面，放在它上一层的机构页更自然）。
- 家长端裁剪：身份卡 + 我的孩子 + 设置；设置里只剩存储空间与关于。
- 「开通引导」「输入邀请码加入」改成**空库才出现**（首页本来就有开通卡，建完还摆着就是噪音）。

### 两处"只留一份实现"
- `utils/invitesheet.js`：邀请码弹层。首屏与机构页都调它，避免两份取码逻辑漂移
  （历史上邀请码就吃过"服务端校验齐了、客户端漏传 orgId"的亏）。
- `utils/fbunread.js`：家长反馈未读数。首页与我的共用一份口径，
  否则某天会分叉成"首页 3、我的 5"，老师只会认为系统坏了。
