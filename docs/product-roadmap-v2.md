# 产品方案 · 橙果课堂 V2：从「记录工具」到「家长的上课助手」

> 状态：**产品方案待拍板，未改代码。**
> 提出：2026-11-08 10:52。用户要点：
> 「小朋友报的课多，家长容易忘，需要上课提醒——今天上什么、几点、在哪，明天后天、下周的日程」；
> 「多机构录入 + 家长能看到孩子所有机构的成果」。
> 本文定位：**产品设计**，不写代码。技术落地细节分散在

## 1. 先纠正一个前提：这不是「加个提醒」

**系统里现在没有「课表」这个东西。**

- `classes` 只有 `session`（当前第几次课），`records` 只有 `date`（哪天录的）。
- `class_courses` 是"课程挂到哪些班"的绑定，不是时间安排。
- 全仓没有"星期几 / 几点 / 教室 / 循环规则"任何一个字段。

所以「提醒今天几点在哪上课」不可能靠加个推送实现 —— **必须先有排课这个业务对象**。
这是本轮真正的工程量，也是价值最大的部分：**老师现在还在微信群里喊"今天上课"**。

---

## 2. 第二个事实：微信不给我们「每周自动推提醒」

官方口径（2026-11，微信开放社区）：长期订阅消息只对政务民生、医疗、交通、金融、教育等
**部分二级类目**开放；**在线教育类目官方明确回复"暂不支持开通长期订阅模板"**。
拿不到长期订阅，就只能走一次性订阅：**用户点一次授权，只能发一条，发完额度清零。**

这意味着：

- ❌ 做不到"每周六早上自动给家长推一条微信提醒"。**任何承诺这个的方案都是假的。**
- ✅ 能做的是「一次性订阅」，用在最关键的**一条**：开课前一天。
- ✅ 真正可靠的路子不在这里 —— 见第 5 节的系统日历。

**产品经理的判断：不要跟平台规则硬碰。用手机系统日历绕过它。**

---

## 3. 核心洞察：三个需求其实是一个产品

你说的三件事，表面是三个功能，本质是**同一个东西**：

> **孩子的成长是一条时间轴。向前是日程，向后是成果。**

- 家长记不住课 → 因为信息散在 3 个机构、5 个微信群、N 个老师私聊里
- 家长看不到全貌 → 因为成果散在各机构的小程序入口里

**真正要卖的不是"提醒"，是"一个地方看全"。** 提醒只是一个附属品。
如果只做提醒、不做聚合，家长还是要在 5 个群里翻——那这个功能就没解决他的问题。

所以产品定位从「课后成果记录工具」升一级：

> **橙果课堂 = 家长手机里的孩子成长日历。**
> 老师用它记录，家长用它看今天去哪上课、上周学了什么。

一句话价值主张：**报了几门课，一个日历看全。**

## 4. 用户与场景

### 4.1 家长（李妈妈）
- 两个孩子，3 家机构，5 门课，横跨周六、周日、周三晚上。
- 痛点不是"没闹钟"，是**"信息不在一个地方"**。她要在 5 个微信群和 3 个老师私聊里拼凑。
- 她真正想问的是：**今天几点要去哪？上周他学得怎么样？**

### 4.2 老师（王老师）
- 周六早上在群里喊"今天上课"，还是有人不来。
- 他不想维护排课表，但如果填一次能省掉每周喊人，他愿意。
- **老师自己才是最需要提醒的人**（他也会忘）。

### 4.3 关键设计约束
- 家长的耐心只有 3 秒：**打开就要看到"今天有没有课"**，不能先选机构再看。
- 老师填表耐心只有 30 秒：排课必须**填一次、管一学期**，绝不能每节课都设。
- 家长不会为这个装新 App：一切在小程序 + 手机日历里完成。

## 5. 功能设计

### 5.1 家长首页重构：一屏三块

```
┌─────────────────────────────┐
│  张小明  ▾        [2 家机构]  │   ← 顶部孩子切换（已有骨架）
├─────────────────────────────┤
│  ● 今天 09:00                │   ← 【今天】最高优先级，大字
│    软笔书法 · 橙果 · 302      │
│    张老师   [导航] [请假]     │
├─────────────────────────────┤
│  明天 16:30  素描 · XX美术     │   ← 【接下来】折叠列表
│  周六 09:00  软笔 · 橙果       │      默认展开 3 条，可看更多
├─────────────────────────────┤
│  最近成果                     │   ← 【成果】现有能力，位置下移
│  11-07 优秀 · 横的起笔稳了     │
└─────────────────────────────┘
```

设计要点：

- **今天没有课 → 整块变成一句"今天没有课，下次是周六 09:00"**，不要留空盒子。
- 「今天」卡片必须是**今天最早的那节课**；一天多节课就并列。
- 只有一家机构、一节课 → 也走这个结构，不搞"高级功能才显示"。
- 底部导航加一个**「日程」页**：周视图，横向 7 天，点某天看当天课程。

### 5.2 排课（老师侧）：填一次，管一学期

**入口**：班级详情 →「上课时间」。

**最小表单（4 个字段，30 秒填完）**：

| 字段 | 说明 | 默认值 |
|---|---|---|
| 每周哪天 | 周一~周日，可多选 | 上次课所在星期 |
| 几点到几点 | 开始/结束 | 上次记录的时间 |
| 在哪 | 教室/地址，可留空 | 上次填的 |
| 老师 | 默认当前操作人 | 班级主讲 |

**展开规则**：设完自动生成未来 8 周的课次，不用一节课一节课点。

**单次调整**（点某一天的课次）：

- **调课** → 改这一次的时间/地点，其他周不变
- **停课** → 这一次取消（放假、老师有事）
- **补课** → 在额外日期加一节
- 三者的区别必须清楚：**改的是"这一次"，不是"以后每周"**。改规则要回班级设置。

**老师侧提醒**：首页顶部一条「今天 3 个班要上课」→ 点进去是今日清单。
这是老师留存的关键，比家长提醒更重要。

**明确不做完整教务**：不检测老师/教室冲突、不做课时包、不做学员排位。
那是培训机构教务系统（校宝、小鹅通）的活，做进去会把这个产品拖死。

### 5.3 提醒的三层设计（这是本方案最关键的部分）

| 层级 | 手段 | 可靠性 | 成本 | 说明 |
|---|---|---|---|---|
| **L1** | 小程序内：首页今日卡 + 日程页 + 角标 | 100%（用户打开就有） | 零 | **必须独立可用**，不依赖任何授权 |
| **L2** | **手机系统日历**（`wx.addPhoneRepeatCalendar`） | 极高（系统闹钟，不依赖微信） | 零 | **主推**，见下 |
| **L3** | 微信一次性订阅消息 | 有限（一次授权一条） | 零 | 只用在「开课前一天」这一条 |

**L2 是产品上的正解**，三个理由：

1. `wx.addPhoneRepeatCalendar` 支持**重复事件**——「每周六 09:00-10:30」写一条，手机自己每周提醒，**一次点击，永久有效**。
2. 不消耗任何订阅额度，不需要反复求家长授权。
3. 家长最信任的是系统日历的提醒（他本来就在用）。

交互：课程详情 / 今日卡片上放一个「**加入手机日历**」，一次写入整个学期所有课次，
文案明确：「以后每周六 9:00 手机自动提醒，不用再打开小程序」。

**L3 只用一次**：开课前一天那条。设计成「上课签到后顺手授权下次」的滚动续期，
**绝不**在打开小程序时硬弹窗（会被投诉，且拒绝后系统永久静默）。

**诚实的沟通话术**：产品里不要写"每周自动微信提醒"，写"**加入手机日历，每周自动提醒**"。

### 5.4 请假闭环（P2）

家长在今日卡片点「请假」→ 老师收到一条待办 → 那天不点他 + 系统不把他算进"未录名单"。
现在家长只能微信私聊老师，老师容易漏。这一条能显著减少"老师以为他会来"。

## 6. 跨机构：家长看全，机构互不可见

沿用 `docs/platform-identity-plan.md` 的结论，**不做物理统一表**：

- 每个孩子的档案仍然**一机构一份**，各存各的成绩评语。
- 平台层只存 `pid`：**这两份是同一个人**。
- 家长看到的"统一"，是**查询时聚合**,不是一张大表。
- 老师端永不跨机构，连提示都不给。

**日程同样聚合**：截图里同一条时间轴上，「软笔 · 橙果」和「素描 · XX美术」并列，
用机构色标区分（橙果绿 / XX美术橙）。这才是"报了很多课"的解药。

**前提**：家长必须确认两份档案是同一个孩子（弹一次「张小明 也在这家上课吗？」）。
平台永不自动合并——双胞胎、同名、代管亲戚孩子会错。

**前置依赖**：`ORG_BOUND` 现在挡住第二家机构，必须先做平台方案的阶段 1。

## 7. 数据模型（产品视角，非最终表结构）

| 对象 | 关键字段 | 谁维护 |
|---|---|---|
| `schedules` 常规排课 | `clsId`、`courseId`、`weekdays[]`、`startTime`、`endTime`、`place`、`teacherId`、`from`、`until` | 老师在班级设置里填一次 |
| `session_changes` 单次调整 | `scheduleId`、`date`、`kind`（调/停/补）、`newStart`、`newPlace` | 老师临时改 |
| `leaves` 请假 | `sid`、`date`、`reason`、`status` | 家长申请、老师确认 |

**家长端"今天有什么"的计算**：

```
未来 14 天 = 按 schedules 的 weekdays 展开
           − session_changes 里的停课
           + 补课
           ± 调课覆盖原时间
           − 已确认的请假
```

**无需新建平台表**，全部仍在机构内，`pid` 只在家长端聚合时用。

## 8. 分阶段路线（每阶段独立可上线）

| 阶段 | 内容 | 用户价值 | 依赖 |
|---|---|---|---|
| **P0** | 排课表单 + 家长「今天/接下来」+ 老师「今日班级」+ 日程周视图 | **最大**：立刻解决"今天上什么课" | 无，可先做 |
| **P1** | 加入手机日历（重复事件）+ 开课前一天一次性订阅 | 高：不用打开小程序也能记得 | P0 |
| **P2** | 请假 + 调课/停课/补课 | 中：少一次群里对账 | P0 |
| **P3** | 家长跨机构聚合（时间线混排 + 机构标签） | 高，但受众小 | 平台方案阶段 1 |

**建议顺序：P0 → P1 → P2 → P3。** P0 单独就有完整价值，且不依赖任何跨机构改造。

## 9. 明确不做（防止越做越重）

- ❌ 完整教务排课（老师/教室冲突检测、课时消耗、排位）
- ❌ 站内即时聊天（微信已经是最好的 IM，做一个必死）
- ❌ 每周自动微信推送（平台不给，别承诺）
- ❌ 家长社区 / 同城拼课 / 老师评价榜
- ❌ 短信通道（成本高、非必要）
- ❌ 老师端跨机构视图

## 10. 验收与指标

**功能验收**
- 家长打开小程序 **3 秒内**能回答"今天有没有课、几点、在哪"。
- 老师设置一次排课，**未来 8 周**家长端全部正确显示。
- 停课一次，那天家长端消失、老师端不提醒；调课一次，只改那一天。
- 加入日历后，手机日历里出现每周重复事件，提前 30 分钟提醒。

**体验指标（上线后用数据看）**
- 排课设置完成率（老师设了班级时间的比例）
- 家长「加入手机日历」点击率
- 今日卡片打开率
- 「老师群里喊上课」是否下降（定性回访）

## 11. 风险与坑

| 风险 | 说明 | 对策 |
|---|---|---|
| **iOS 日历权限坑** | iOS 选"仅添加事件"时，接口返回成功但实际静默失败，`fail` 不触发 | 先 `wx.getSetting` 检查 `scope.addPhoneCalendar`；失败给明确引导；Android 无此问题 |
| **老师不愿填排课** | 最大失败风险：表单太长就不填 | 4 个字段、默认值取上次、可跳过（不填就不显示日程，其余功能照常） |
| **家长不装日历** | 部分家长不点 | L1 小程序内必须独立完整，日历只是增强 |
| **订阅消息被投诉** | 硬弹窗会被投诉、且拒绝后永久静默 | 只在"上课签到后"这一个自然节点请求 |
| **跨机构提前做** | P3 依赖平台阶段 1，顺序错了会返工 | 严格按 P0→P3，不跳步 |
| **排课与课次冲突** | 现有 `session`（第几次课）与排课的"第几节"是两套编号 | 排课只负责**时间**，`session` 仍由"结清"推进，两者不混 |

## 13. 成长传播（**待排期，本轮不做**，2026-11-08 记录）

用户明确：这块能力以后要考虑，现在不上。方案已单独成文：**`docs/growth-share-plan.md`**。

一句话：把已有的 `records`（分数/评语/照片/语音）装订成「学期成长报告」，
家长主动发朋友圈、老师发班级群、机构当招生案例 —— 一份数据，三个渲染器。

为什么挂在路线图里而不是孤零零放一份文档：它是**同一批数据的第二种用途**。
排课与今日卡解决"家长愿不愿意每天打开"，成长报告解决"家长愿不愿意告诉别人"。
两者共用 `records` 与 `terms`，`terms.status = archived` 就是它的触发锚点，
**做 P0 排课时顺手把 `terms` 结课动作留出来，将来接报告不用返工**。

已知前置缺口（真要做时才补，现在不动）：
- 没有分享出口：全项目仅 `pages/mgr/mgr.js` 一处 `onShareAppMessage`；`wx.canvasToTempFilePath` 0 处
- 没有小程序码（`wxacode.getUnlimited` 云调用）与免登录只读展示路由
- 照片不分"作品 / 花絮"；没有学期总评字段

排期建议（都是可独立上线的小段）：P0 海报 1 天 → P1 七屏 + 展示路由 2 天 →
P2 情感三件套 2 天 → P3 班级批量 2 天 → P4 H5 微电影 4 天 → P5 年度回顾 3 天。

**触发条件**：等排课 / 今日卡上线、家长周打开率稳定之后再看。现在做等于把好东西
投向一个还没有人每天进来的产品。
