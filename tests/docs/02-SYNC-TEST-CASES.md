# 同步复制测试用例 — 橙果课堂

> 执行方式标注：`LLM` = 可粘贴给 LLM 自主执行（多为 node tests 断言 + 代码走查）；`真机` = 人工。
> 本类多数用例在 `tests/verify_pull.js` / `verify_sync.js` 已有自动化实现，执行 = 跑套件 + 核对断言点，不要重写脚本。

---

### TC-SYNC-001: 家长冷启动 pull 只含自家孩子

**优先级**: P0 **类型**: 集成 **预估时间**: 3 分钟 **执行方式**: LLM

**前置条件**:
- `node tests/run.js` 环境可用（Node 16+）

**测试步骤**:
1. 运行 `node tests/run.js`，定位 verify_pull 套件
2. 核对家长相关断言：students 按 studentIds 过滤、enrollments 按 `studentId`（不是 `id`）过滤

**预期结果**:
✅ verify_pull 13 项全过
✅ 家长 mock 库中拿不到他人孩子的 records/students

**通过/失败标准**:
- ✅ 通过：套件绿
- ❌ 失败：家长可见非自家数据 = A01 破口，P0

**需关注的潜在缺陷**:
- enrollments 过滤字段回退成 `id`（1148 曾犯，防回归重点）

**前置条件**:

2. 核对第二轮 pull 使用 `srvAt >` 游标，已拉记录不再下发

**预期结果**:
✅ 第二轮返回增量为空（无新数据时）
✅ 本地无重复 _id

**通过/失败标准**:

- ❌ 失败：全量重发或漏数据

**需关注的潜在缺陷**:
- 服务器时间与本地 updatedAt 时区/精度不一致导致抖动

**前置条件**:
- syncv2 pull 实现含截断逻辑

**测试步骤**:
1. 走查 syncv2：单集合 >500 条返回截断标记 + srvAt
2. 核对 count 统计与数据查询使用同一 where（不要数据收窄了、count 还是全量）

**预期结果**:
✅ 大机构数据可分页拉全；截断计数与过滤条件一致

**通过/失败标准**:
