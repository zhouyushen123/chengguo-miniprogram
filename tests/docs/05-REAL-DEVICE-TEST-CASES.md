### TC-REAL-003: 被分新班后历史自动补齐 ⭐核心验证点

**优先级**: P0 **类型**: 端到端 **预估时间**: 10 分钟

**前置条件**:
- 老师账号当前只带 1 个班（A 班），A 班已有若干历史记录
- 有管理员可操作分班

**测试步骤**:
1. 老师端正常使用一次（确认基线正常）
2. 管理员在后台给老师加 B 班（B 班已有历史记录）
3. 老师端杀进程重启，触发 pull
4. 观察：是否出现 B 班及其学生、历史记录

**预期结果**:
✅ B 班学生与历史记录自动补齐，无需手动刷新
✅ A 班数据不丢

**通过/失败标准**:
- ✅ 通过：rescoped → 游标归零 → 重拉全链路真机生效
- ❌ 失败：B 班不出现 / 历史缺失 = P0（RISK-001 命中）

**需关注的潜在缺陷**:
- pull 触发时机：重启后是否自动 pull 还是需手动进某页
- rescoped 标记消费后未清理 → 每次重启都全量重拉（流量异常）

### TC-REAL-004: 两台设备冲突找回 ⭐核心验证点

**优先级**: P0 **类型**: 端到端 **预估时间**: 12 分钟

**前置条件**:
- 两台设备（或一台真机+工具模拟器）登录同一老师账号
- 存储页（pkg-low/storage）可进入

**测试步骤**:
1. 设备 1、设备 2 各改同一条记录的评语（内容不同）
2. 先后触发同步（设备 1 先 push，设备 2 后 push 但本地改动在先）
3. 设备 2 进「存储」页查看「被覆盖的改动」卡片
4. 点找回按钮

**预期结果**:
✅ 冲突卡片出现且列出被覆盖内容
✅ 点找回后该内容重新生效并可同步

**通过/失败标准**:
- ✅ 通过：败者可见、可找回（A2 能力闭环）
- ❌ 失败：卡片不出现（误判无冲突）或找回无效 = P0（RISK-002 命中）

**需关注的潜在缺陷**:
- 两设备时钟偏差导致冲突判定异常
- conflicts 超 20 条时旧冲突被挤掉
